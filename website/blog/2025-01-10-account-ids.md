我们最近得知，有一个自定义仓库插件能够读取并存储其他用户的唯一永久分配角色 ID（亦称 Content ID）和账户 ID。由于这在玩家群体中引起了相当程度的担忧，我们想就我们的观点、该插件的背景以及 Account ID 的运作方式发表官方声明。

首先，Dalamud 项目从根本上不认可该插件，也不认为它有必要被创建。Dalamud 的设计理念是改善游戏体验和增加生活质量改进，而不是支持那些有意或无意损害他人体验的人。

随着 Dawntrail 中引入的[新黑名单功能](https://youtu.be/OxVWTktvt_M?t=11495)，游戏服务器现在会在特定条件下发送玩家角色 Content ID 和 Account ID。Account ID 是一个大数字，允许用户将同一账户上的不同角色关联起来。同一服务账号下的所有角色共享此号码。在常规操作中，这些 ID 用于让游戏过滤掉聊天、世界可见区域、搜索信息、市场公告板等区域中被黑名单或静音的角色的消息。由于过滤逻辑在客户端执行，客户端需要知道每个角色所属的账户信息，才能正确隐藏被黑名单角色的小号。

Dalamud 项目无法阻止插件获取这些值。虽然 Dalamud 自身的 API 并不暴露它们，但插件可以访问游戏原始内存和数据结构，可以访问游戏知道的任何信息（包括这些 Account ID）。即使 Dalamud 能够限制对此数据的访问，这也是无效的，因为这些 ID 仍然通过网络发送到游戏客户端。任何能够读取游戏数据（如 Cheat Engine）或嗅探网络数据（如 ACT、Wireshark）的工具都能捕获和提取这些值。出于类似原因，反作弊软件也对此无效。唯一可行的解决方案是修改黑名单系统，使其不向客户端发送原始 ID。

即使考虑到所有这些，您可能仍有疑问：我们是否可以对可能试图使用此数据的个别（自定义仓库）插件采取措施或阻止它们。虽然我们对提交到[官方仓库的插件有显著的控制权](https://dalamud.dev/plugin-development/plugin-submission)，可以强制执行关于数据使用的某些规则，但[由于设计原因，我们无法控制自定义仓库的插件](https://dalamud.dev/plugin-development/restrictions/#i-dont-like-plugin-x-can-you-block-it-or-delete-it)。虽然 Dalamud 确实有一种机制可以阻止插件加载，但这套系统仅设计用于插件导致崩溃或执行意外操作的情况。该系统并非设计用于永久禁止插件，任何试图将其用于此目的的行为都会在几秒钟内被绕过。

整个情况是 Dawntrail 中引入的黑名单变更的副作用，提取和跟踪 Account ID 的工具是不可避免的发展，并不局限于插件生态系统。我们鼓励玩家在游戏中利用黑名单和举报功能，如果他们对被跟踪或骚扰有顾虑的话。
